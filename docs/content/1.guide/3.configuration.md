# Konfiguration

## Code-Standards

- TypeScript strict mode ueberall
- Zod Schemas als Single Source of Truth fuer Typen
- Keine `any` Types — `unknown` + Type Narrowing verwenden
- Bevorzugt `Bun.file()` / `Bun.write()` gegenueber Node.js `fs` API
- Git Commits sollen atomar und beschreibend sein

## Paket-Benennung

| Pattern | Beispiel |
|---------|----------|
| Core-Pakete | `@openpress/core`, `@openpress/ui`, `@openpress/schemas` |
| Themes | `@openpress/theme-tailwind-plus`, `@openpress/theme-material-expressive` |
| Features | `@openpress/feature-contact-form`, `@openpress/feature-booking` |
| POCs | `@openpress/poc-storage`, `@openpress/poc-editor` |

## Schema-Konventionen

- Alle Datenstrukturen werden als Zod-Schemas definiert
- TypeScript-Types werden mit `z.output<>` abgeleitet (nicht `z.infer`) fuer Schemas mit `.default()` Feldern
- `readJSON`/`writeJSON` verwenden `ZodType<T, any, any>` fuer korrekte Output-Typen

## IDs

- ULID fuer alle persistenten Entity-IDs
- Sortierbar, eindeutig, URL-safe

## Runtime-Hinweise

- **Server (Nitro)** laeuft auf Node.js — niemals `Bun.*` APIs im Server-Code verwenden
- **Git-Operationen** verwenden `node:child_process` im Server
- **Client & Tests** koennen Bun-APIs nutzen

## Nuxt-Konfiguration

```typescript
// nuxt.config.ts
export default defineNuxtConfig({
  modules: ['@openpress/core'],
  openpress: {
    contentDir: './content',
    editPath: '/_edit',
    storage: {
      autoCommit: true
    }
  }
})
```
