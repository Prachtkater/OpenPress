# Architektur-Ueberblick

## Technische Architektur

- **Runtime**: Bun
- **Framework**: Nuxt 3 (als Modul unter `/_edit`)
- **Typesafety**: Zod fuer Schema-Validierung, TypeScript fuer das gesamte Projekt
- **Editor-Engine**: Tiptap fuer Inline-Rich-Text, Custom Vue-Wrapper fuer Block-Composition
- **IDs**: ULID fuer persistente, sortierbare Block-IDs

## Vier Schichten

OpenPress ist in vier Schichten organisiert:

### 1. Schema Layer (`@openpress/schemas`)

Die "Source of Truth". Jedes Datenstueck — von einem einzelnen Textblock bis zur gesamten Site-Konfiguration — wird mit **Zod** validiert. Das stellt Typsicherheit im gesamten Monorepo sicher.

### 2. UI Engine (`@openpress/ui`)

Das "Nervensystem". Diese Schicht verwaltet den Kontext-Baum und stellt State (Page, Site, Mode) jeder Komponente bereit. Sie rendert Sections und Slots unabhaengig von einem bestimmten Design.

### 3. Feature Layer (`@openpress/feature-*`)

Die "Faehigkeiten". Modulare Pakete, die spezifische Funktionalitaet hinzufuegen, wie die **Media Library**, **Buchungssystem** oder **Kontaktformulare**. Features sind entkoppelt und koennen in jede OpenPress-Instanz eingebunden werden.

### 4. Theme Layer (`@openpress/theme-*`)

Die "Visuelle Identitaet". Themes liefern die CSS-Klassen und visuellen Regeln ueber das Liquid Glass Token-System.

## Hierarchischer Fluss

Die Architektur folgt einem strikten Top-Down-Fluss:

```
OpProvider (Global State)
  └── OpSection (Layout Container)
        └── OpSlot (Content Area)
              └── Content Blocks (Visuelle Elemente)
```

- **OpProvider**: Orchestriert die globale Umgebung
- **OpSection**: Definiert einen semantischen Bereich einer Seite (z.B. Hero, Features)
- **OpSlot**: Ein benannter Container innerhalb einer Section fuer eine geordnete Liste von Blocks
- **Blocks**: Die finalen Knoten im Baum (z.B. RichText, Image, Button)

## Ordnerstruktur

```
packages/core/src/
  module.ts                    # Der Einstiegspunkt
  runtime/
    components/                # Op-Komponenten
    composables/               # useOpenPress, etc.
    server/                    # API-Routes fuer Git-Interaktion
    pages/                     # Die /_edit UI
playground/                    # Test-Umgebung
content/                       # JSON-Inhalte
```

## Design-Prinzipien

- **Modular**: Features oder Themes austauschen, ohne den Core zu aendern
- **Vorhersehbar**: Daten fliessen klar von oben nach unten
- **Erweiterbar**: Neue "Aeste" (Features) einfach hinzufuegen
